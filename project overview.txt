PROJECT OVERVIEW - REMINDCARE WHATSAPP BOT

Ringkasan
RemindCare adalah bot WhatsApp berbasis Node.js untuk mendampingi ibu hamil.
Fokus utamanya adalah pengingat konsumsi tablet FE harian, pencatatan jawaban
"Sudah" atau "Belum", edukasi menjelang persalinan, validasi apakah user sudah
melahirkan, pendataan persalinan, serta reminder kunjungan masa nifas dan
neonatal. Bot juga punya reminder kelas ibu hamil 4 minggu setiap hari Minggu
pagi. Project juga menyediakan dashboard admin web untuk melihat data user, log
reminder, log kunjungan, dan export CSV.

Tech Stack
- Runtime: Node.js
- WhatsApp integration: whatsapp-web.js + LocalAuth
- Web server admin: Express
- Database: SQLite melalui sqlite3
- Tanggal dan waktu: Luxon, timezone Asia/Jakarta
- QR login WhatsApp: qrcode-terminal

Struktur Project
- index.js
  File utama. Berisi konfigurasi, daftar pertanyaan onboarding, daftar jadwal
  kunjungan postpartum, helper parsing/validasi, akses database, handler pesan
  WhatsApp, handler poll, loop scheduler, command admin WhatsApp, dan admin web.
- package.json
  Script utama: npm start dan npm test.
- tests/parse.test.js
  Unit test untuk parsing, validasi waktu/tanggal, hitung HPL, validasi
  persalinan, postpartum, retry backoff, dan command persalinan.
- data/remindcare.db
  Database SQLite runtime. File ini dibuat/dipakai saat aplikasi berjalan.
- data/admin_web_password.txt
  Password admin web yang dibuat otomatis jika ADMIN_WEB_PASSWORD tidak diset.
  Isi file ini sensitif dan tidak perlu dicantumkan di dokumentasi/log.
- .wwebjs_auth dan .wwebjs_cache
  Data session/cache WhatsApp Web lokal.
- daftar-fitur-flow-trigger.txt
  Dokumentasi fitur, trigger, dan flow yang sudah ada sebelumnya.
- data backup/remindcare.db
  Backup database.
- firebase.json dan public/index.html
  Konfigurasi Firebase Hosting sederhana untuk redirect link materi kelas ibu
  /minggu1, /minggu2, dan /minggu3.

Cara Menjalankan
1. Install dependency:
   npm install
2. Jalankan bot:
   npm start
3. Scan QR WhatsApp yang muncul di terminal.
4. Dashboard admin berjalan di:
   http://localhost:3030/admin

Script
- npm start
  Menjalankan index.js.
- npm test
  Menjalankan tests/parse.test.js.

Flow Runtime Utama
1. Aplikasi start.
2. Folder data dipastikan ada.
3. Database SQLite dibuka di data/remindcare.db.
4. Tabel dan kolom database dibuat/migrasi otomatis.
5. Admin web Express dijalankan jika ADMIN_WEB_ENABLED tidak bernilai 0/false.
6. Client WhatsApp Web dibuat dengan LocalAuth.
7. Jika session belum ada, QR ditampilkan di terminal.
8. Saat WhatsApp ready, bot mulai menerima pesan dan vote poll.
9. Scheduler reminder berjalan setiap 30 detik.
10. Scheduler mengambil user aktif, allowed, tidak blocked, punya reminder_time,
    lalu memproses reminder FE, validasi persalinan, dan kunjungan postpartum.

Database
1. users
   Menyimpan profil user, status onboarding/active/paused/completed, HPHT,
   pengaturan reminder, flag admin/allowed/blocked, state poll FE, state poll
   persalinan, data persalinan, dan timestamp edukasi postpartum.

2. reminder_logs
   Menyimpan log harian reminder FE per user dan tanggal. Jawaban dicatat
   sebagai "Sudah" atau "Belum", termasuk counter masing-masing jawaban.

3. postpartum_visit_logs
   Menyimpan jadwal dan status reminder kunjungan postpartum/neonatal per user:
   kode kunjungan, due_at, status pengiriman teks/poll, poll_message_id,
   retry state, jawaban, counter jawaban, dan waktu respon.

Konfigurasi Environment Penting
- PREGNANCY_WEEKS_LIMIT
  Batas masa reminder kehamilan. Default 42 minggu.
- DELIVERY_VALIDATION_START_WEEK
  Minggu awal validasi persalinan otomatis. Default 39.
- ENFORCE_ALLOWLIST
  Jika true/1, nomor user harus ada di allowlist atau admin.
- ADMIN_WA_IDS
  Daftar wa_id admin WhatsApp.
- ALLOWLIST_WA_IDS
  Daftar wa_id yang diizinkan saat allowlist aktif.
- RATE_LIMIT_MAX_PER_MINUTE
  Batas pesan/vote per menit. Default 20.
- RATE_LIMIT_WINDOW_MS
  Window rate limit. Default 60000 ms.
- RATE_LIMIT_COOLDOWN_MS
  Durasi cooldown rate limit. Default 120000 ms.
- POLL_MAX_RESPONSES_PER_DAY
  Batas jawaban poll per jenis jawaban per hari. Default 2.
- ADMIN_WEB_ENABLED
  Admin web aktif secara default. Set 0/false untuk mematikan.
- ADMIN_WEB_PORT
  Port admin web. Default 3030.
- ADMIN_WEB_USER
  Username admin web. Default admin.
- ADMIN_WEB_PASSWORD
  Password admin web dari env. Jika kosong, sistem memakai/membuat file
  data/admin_web_password.txt.
- ADMIN_WEB_SESSION_TTL_MS
  Masa berlaku session admin web. Default 8 jam.
- ADMIN_WEB_COOKIE_SECURE
  Cookie secure untuk admin web. Aktif otomatis saat NODE_ENV=production.
- MOTHER_CLASS_BASE_URL
  Host link materi kelas ibu. Default https://remindcares.web.app.
- MOTHER_CLASS_WINDOW_START_HOUR
  Jam awal window reminder kelas ibu hari Minggu. Default 9.
- MOTHER_CLASS_WINDOW_END_HOUR
  Jam akhir window reminder kelas ibu hari Minggu. Default 12.
- REMINDER_LOG_RETENTION_DAYS
  Retensi log reminder harian. Default 180 hari.
- POLL_RETRY_BASE_DELAY_MS
  Delay dasar retry poll. Default 5 menit.
- POLL_RETRY_MAX_DELAY_MS
  Batas maksimal delay retry poll. Default 30 menit.
- REMINDER_LOOP_CONCURRENCY
  Jumlah user yang diproses paralel per batch scheduler. Default 10.
- PUPPETEER_EXECUTABLE_PATH
  Path browser Chromium/Chrome/Edge jika ingin menentukan manual.
- PUPPETEER_NO_SANDBOX atau DISABLE_CHROME_SANDBOX
  Menonaktifkan sandbox Chromium jika dibutuhkan environment server.

Flow User Baru dan Onboarding
Trigger:
- Nomor baru mengirim start atau mulai di chat private.
- Pesan dari grup, status, dan target direct unsupported diabaikan.
- Jika allowlist aktif, nomor harus allowed atau admin.

Alur:
1. Bot membuat record user dengan status onboarding.
2. Bot mengirim pertanyaan onboarding pertama.
3. User menjawab pertanyaan secara berurutan.
4. Jawaban divalidasi sesuai tipe data.
5. Jika user menolak diingatkan oleh RemindCare, status menjadi active tetapi
   reminder_time dikosongkan dan reminder tidak aktif.
6. Jika onboarding selesai, status menjadi active, reminder_time tersimpan, dan
   bot mengirim konfirmasi jadwal reminder.

Pertanyaan Onboarding
1. Nama ibu.
2. Usia.
3. Kehamilan ke berapa.
4. HPHT dengan format tanggal valid.
5. Apakah rutin mengonsumsi obat.
6. Apakah masih mengonsumsi teh.
7. Siapa yang biasanya mengingatkan minum obat.
8. Apakah mau diingatkan RemindCare.
9. Jam reminder harian.

Flow Pesan Pembuka
Trigger:
- Nomor baru mengirim pesan apa pun selain start/mulai.

Alur:
1. Bot mengirim perkenalan singkat RemindCare.
2. Bot meminta user mengetik start.
3. User belum masuk onboarding sebelum mengirim start/mulai.

Flow Reminder Harian Tablet FE
Trigger:
- Scheduler 30 detik.
- User status active, allow_remindcare=1, tidak blocked, punya reminder_time.
- Waktu sekarang sudah mencapai reminder_time.
- Poll hari ini belum terkirim.

Alur:
1. Bot mengirim teks reminder harian.
2. Bot mengirim poll "Sudah minum tablet FE hari ini?".
3. Bot menyimpan last_reminder_date dan last_poll_message_id.
4. Bot membuat/ensure reminder_logs untuk tanggal tersebut.
5. Jika pengiriman poll gagal, fail_count dan last_attempt_at diupdate untuk
   retry dengan exponential backoff.

Flow Jawaban Reminder FE
Trigger:
- User membalas teks yang bisa diparse sebagai "Sudah" atau "Belum".
- Atau user vote pada poll FE aktif.

Alur:
1. Bot memastikan poll/log hari ini relevan.
2. Jawaban dicatat ke reminder_logs.
3. Counter response_sudah_count atau response_belum_count dinaikkan.
4. Jika batas jawaban harian sudah tercapai, bot memberi tahu user agar tidak
   mengirim ulang.
5. Jika jawaban "Sudah", bot mengirim terima kasih.
6. Jika jawaban "Belum", bot mengingatkan untuk minum tablet.

Flow Edukasi Fase Persalinan
Trigger:
- Scheduler harian saat user berada di usia kehamilan minggu 37 sampai 41.
- Pesan fase persalinan belum dikirim pada hari tersebut.
- User belum terkonfirmasi sudah melahirkan.

Alur:
1. Bot menghitung usia kehamilan dari HPHT.
2. Bot memilih pesan edukasi sesuai minggu.
3. Pada minggu 40, pesan menyertakan HPL.
4. Bot menyimpan last_labor_phase_message_date.

Flow Validasi Persalinan
Trigger otomatis:
- Usia kehamilan >= DELIVERY_VALIDATION_START_WEEK, default minggu 39.
- User belum terkonfirmasi sudah melahirkan.
- Waktu sekarang masuk window 2 jam sebelum reminder_time.
- Poll validasi hari itu belum dikirim.

Trigger manual:
- User mengirim cek persalinan, konfirmasi persalinan, atau persalinan.

Alur:
1. Bot mengirim poll "Apakah Ibu sudah melahirkan?".
2. Bot menyimpan last_delivery_poll_message_id dan delivery_poll_stage.
3. Jawaban "Belum" dicatat dan bot mengirim pesan dukungan/tanda bahaya.
4. Jawaban "Sudah" memulai pendataan persalinan bertahap.

Flow Pendataan Persalinan
Trigger:
- User menjawab "Sudah" pada validasi persalinan.
- Atau user mengulang melalui edit persalinan jika data persalinan sudah ada.

Pertanyaan:
1. Tanggal melahirkan.
2. Jam melahirkan.
3. Tempat melahirkan.
4. Penolong persalinan.
5. Apakah persalinan dengan penyulit.
6. Jenis kelamin bayi.
7. Berat badan bayi saat lahir dalam gram.
8. Keluhan ibu saat ini.

Validasi:
- Tanggal harus valid.
- Tanggal tidak boleh sebelum HPHT.
- Tanggal tidak boleh di masa depan.
- Jam harus format valid 24 jam.
- Kombinasi tanggal dan jam tidak boleh di masa depan.
- Pertanyaan ya/tidak harus bisa diparse.
- Berat bayi harus valid dalam gram.

Alur selesai:
1. Data persalinan disimpan.
2. delivery_data_completed_at diisi.
3. delivery_data_step direset ke 0.
4. Log kunjungan postpartum lama dibersihkan agar jadwal baru bisa dibuat.
5. Bot mengirim edukasi masa nifas/neonatal.

Flow Postpartum dan Kunjungan KF/KN
Trigger:
- Data persalinan sudah lengkap.
- Scheduler masuk window 2 jam sebelum reminder_time.
- Due time kunjungan sudah tercapai.
- Kunjungan tersebut belum dikirim/jawab.

Jadwal:
- KF/KN 1: 6 jam sampai 48 jam pasca persalinan.
- KF/KN 2: 3 sampai 7 hari pasca persalinan.
- KF/KN 3: 8 sampai 28 hari pasca persalinan.
- KF 4: 29 sampai 42 hari pasca persalinan.

Alur:
1. Bot mengirim edukasi postpartum satu kali jika belum pernah terkirim.
2. Bot memastikan log kunjungan ada di postpartum_visit_logs.
3. Jika due_at sudah tercapai, bot mengirim teks pengingat kunjungan.
4. Bot mengirim poll konfirmasi kunjungan.
5. Bot menyimpan poll_message_id untuk tracking jawaban.
6. Maksimal satu kunjungan dikirim per siklus scheduler agar chat tidak penuh.
7. Jika pengiriman poll gagal, retry mengikuti exponential backoff.

Flow Reminder Kelas Ibu
Trigger:
- User sudah selesai onboarding/registrasi dan reminder aktif.
- Scheduler berjalan pada hari Minggu dalam range 09:00 sampai 12:00 WIB.
- Reminder kelas ibu minggu tersebut belum dikirim.
- Program belum selesai.

Alur:
1. Saat onboarding selesai, state reminder kelas ibu diaktifkan untuk user.
2. Minggu 1 bot bertanya apakah Ibu sudah pernah mengikuti kelas ibu.
3. Jika jawab "Sudah", bot menanyakan lokasi kelas dan jumlah keikutsertaan
   1 sampai 4 kali.
4. Jika jumlahnya 4, bot mengucapkan selamat dan program kelas ibu selesai.
5. Jika jumlahnya 1 sampai 3, bot mengirim materi minggu 1 dan melanjutkan
   reminder kelas ibu pada hari Minggu berikutnya.
6. Jika jawab "Belum", bot menanyakan wilayah cakupan Ibu lalu mengirim materi
   minggu 1.
7. Minggu 2 bot mengirim pesan pertemuan kedua dan link materi minggu 2.
8. Minggu 3 bot mengirim pesan pertemuan ketiga dan link materi minggu 3.
9. Minggu 4 bot mengingatkan Ibu datang langsung ke faskes sekitar yang
   membuka kelas ibu, seperti posyandu, puskesmas, klinik, atau faskes lain.
10. Setelah minggu 4, program reminder kelas ibu ditandai selesai.

Link materi kelas ibu:
- https://remindcares.web.app/minggu1 redirect ke Google Drive pertemuan 1.
- https://remindcares.web.app/minggu2 redirect ke Google Drive pertemuan 2.
- https://remindcares.web.app/minggu3 redirect ke Google Drive pertemuan 3.
Redirect tersedia di dua tempat:
- Route Express di repo bot.
- Konfigurasi Firebase Hosting di firebase.json jika domain web.app dideploy
  dari repo ini.

Flow Jawaban Kunjungan Postpartum
Trigger:
- User vote pada poll kunjungan postpartum.
- Atau user mengirim teks "Sudah" / "Belum" saat ada kunjungan pending.

Alur:
1. Bot mencari log kunjungan berdasarkan poll_message_id atau pending terbaru.
2. Jawaban dicatat ke postpartum_visit_logs.
3. Counter jawaban "Sudah" atau "Belum" dinaikkan sesuai limit harian.
4. Jika "Sudah", bot mengingatkan untuk lanjut kunjungan berikutnya.
5. Jika "Belum", bot menyarankan segera kunjungan ke tenaga kesehatan.

Flow Auto Complete Program
Trigger:
- Usia kehamilan melewati PREGNANCY_WEEKS_LIMIT.
- Delivery sudah terkonfirmasi.
- Tidak ada monitoring postpartum aktif.
- User tidak sedang mengisi data persalinan.
- Atau user sudah menjawab "Sudah" untuk kunjungan KF 4.

Alur:
1. Status user menjadi completed.
2. allow_remindcare menjadi 0.
3. Bot tidak mengirim reminder tablet FE lagi.
4. Bot mengirim notifikasi bahwa masa pengingat selesai.

Command User
- start / mulai
  Mengaktifkan reminder. Jika jam belum ada, user diarahkan mengisi jam.
- stop / berhenti
  Menjeda reminder dan mengubah status menjadi paused.
- ubah jam 17:00 / set jam 17:00 / jam 17:00
  Mengganti reminder_time dan mengaktifkan reminder.
- help / menu
  Menampilkan daftar perintah.
- info / informasi
  Menampilkan ringkasan data ibu, status reminder, HPL, status persalinan,
  dan progres kunjungan postpartum.
- cek persalinan / konfirmasi persalinan / persalinan
  Memulai validasi persalinan manual.
- edit
  Menampilkan menu edit.
- edit data
  Reset data profil, kehamilan, persalinan, dan mulai onboarding dari awal.
  Perlu konfirmasi dua kali dalam 5 menit.
- edit persalinan
  Reset data persalinan dan jadwal postpartum, lalu isi ulang data persalinan.
  Perlu konfirmasi dua kali dalam 5 menit.
- delete / hapus
  Hapus akun, reminder_logs, dan postpartum_visit_logs. Perlu konfirmasi dua
  kali dalam 5 menit.
- batal
  Membatalkan konfirmasi edit/hapus.
- about
  Menampilkan info singkat project.
- website
  Menampilkan alamat website.

Command Admin WhatsApp
Syarat:
- User harus punya is_admin=1. Admin bisa diset melalui ADMIN_WA_IDS.

Daftar command:
- admin help
  Menampilkan command admin.
- admin stats
  Menampilkan statistik total user, active, allowed, dan blocked.
- admin allow <wa_id>
  Mengizinkan nomor.
- admin block <wa_id>
  Memblokir nomor.
- admin unblock <wa_id>
  Membuka blokir nomor.
- admin purge logs <hari>
  Menghapus reminder_logs yang lebih lama dari jumlah hari tertentu.

Proteksi dan Mekanisme Operasional
- Private chat only: grup dan status diabaikan.
- Allowlist optional melalui ENFORCE_ALLOWLIST.
- Blocklist user melalui admin command.
- Rate limit pesan/vote per user.
- Konfirmasi dua kali untuk aksi edit data dan delete.
- Retry poll dengan exponential backoff.
- Cleanup reminder_logs otomatis sekali per hari.
- Migration kolom/tabel otomatis saat startup.
- Admin web memakai header keamanan dasar:
  X-Frame-Options, X-Content-Type-Options, dan Referrer-Policy.

Catatan Teknis
- index.js saat ini bersifat monolith. Semua logic bot, database, admin web,
  dan scheduler berada di satu file.
- Database dan session WhatsApp bersifat lokal. Backup perlu dilakukan dari
  data/remindcare.db dan folder session jika ingin memindahkan server.
- Jangan membagikan isi data/admin_web_password.txt.
- Jika admin web dipakai di production, sebaiknya set ADMIN_WEB_PASSWORD via
  environment variable dan jalankan di balik HTTPS/reverse proxy.
- Karena whatsapp-web.js bergantung pada WhatsApp Web, runtime membutuhkan
  browser Chromium/Chrome/Edge yang bisa dijalankan oleh Puppeteer.
